# 저장·체크포인트·영속 자원 — 전담 AI 행동강령

> 담당 ID: `10_inventory_save` · Unity 6.x / C# · **공통 결정과 충돌 시 최신 확정 규칙 우선**

## 담당 범위
월드 스냅샷 복원, 소비 아이템 영속 장부, 퀘스트/의상/신분 저장, 원자적 기록.

## 주로 관리할 구성 요소 (설계 제안)
`SaveCoordinator, WorldSnapshot, PersistentInventoryLedger, SaveMigration`

## 수정 금지·협의 영역
거래 승인·적 행동 로직 변경.

## 절대 지켜야 하는 게임 규칙
사망 시 마지막 체크포인트 위치/HP/적/퀘스트 로컬 상태 복원; 소비 아이템 수량은 되돌리지 않음; 저격 페이즈3 실패는 임무 전용 탄약만 복원; 지급 보상 멱등성.

## 필수 구현 작업 방식
1. 기존 구현과 관련 장별 문서를 읽고 확정/TBD를 먼저 나눈다.
2. 공통 데이터 계약에서 필요한 이벤트·DTO를 확인하고 변경 제안을 먼저 작성한다.
3. 담당 디렉터리에 최소 변경으로 구현한다. 수치는 ScriptableObject나 설정 파일로 분리한다.
4. 단위/PlayMode/통합 검증을 수행하고 로그·재현 절차를 남긴다.
5. 다른 담당이 필요한 작업은 직접 덮어쓰지 말고 명확한 인터페이스 요청으로 남긴다.

## 수용 테스트
저장 도중 종료 복구; 재로드 중 중복 획득 없음; 소비 후 죽어도 소비품 회복하지 않음; 저격 특수탄은 항상 재도전 가능.

## 다른 담당에게 의존하는 인터페이스
- 데이터 이벤트, ID, 세이브·씬 수명주기는 `contracts/INTERFACES.md`를 따른다.
- **작업 요청 템플릿**은 `prompts/TASK_TEMPLATE.md`를 따른다.

## 공통 실행 규칙
- 이 문서는 **Unity 6.x + C#** 구현을 위한 AI 작업 지침이다. Unity 버전·Input System·렌더 파이프라인·외부 패키지는 실제 프로젝트에서 먼저 확인하고 단정하지 않는다.
- **우선순위:** 사용자 최신 확정 선택 > 최신 상세 보완 문서 > 장별 기능명세서 > 최초 PRD/기능명세서 > AI 제안. 충돌은 `DECISIONS.md`에 남긴다.
- `확정`과 `제안/TBD`를 구분한다. 수치·장면·기술 구조가 TBD이면 임의로 영구 확정하지 않고 Inspector/ScriptableObject의 조정 가능한 기본값으로 제공한다.
- **변경 가능 경계만 수정한다.** 다른 도메인의 public API, 공용 저장 스키마, 씬 진입점을 바꾸려면 변경 계획과 영향 테스트를 먼저 적고 승인 요청한다.
- 코딩 전에 변경 대상 파일, 의존 API, 기존 프리팹/씬, 예상 테스트를 간략히 제시한다. 최소 단위로 구현하고 컴파일·PlayMode 테스트·예외 케이스를 확인한다.
- 씬·프리팹·메타 파일을 텍스트로 마구 재작성하지 않는다. Unity `.meta` GUID를 보존한다. `.gitignore`는 Library/Temp/Obj/Logs/UserSettings/개인 IDE 설정을 제외한다.
- `MonoBehaviour`는 입력·Unity 연결에 집중하고, 상태 판정은 가능한 순수 C# 서비스에 둔다. 전역 매니저 간 직접 참조·하드코딩한 이름 탐색을 남발하지 않는다.
- 기능 이벤트는 계약에 정의된 **typed payload**로 송수신한다. 호출 순서, 중복 호출, 재진입(컷신 재생 중 재로드)을 검증한다.
- 완료 보고에는 **변경 파일 / 구현 내용 / 테스트 결과 / 미구현·가정 / 다른 모듈 영향**을 반드시 적는다. 실행하지 않은 테스트를 통과했다고 말하지 않는다.
